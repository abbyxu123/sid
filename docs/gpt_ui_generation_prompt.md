# GPT UI Generation Prompt For CatTV

Date: 2026-07-25

Use this prompt to generate final UI preview images and no-text background assets for the CatTV small hardware screen.

## Copy This Prompt

```text
你是一个资深游戏 UI / 硬件小屏幕 UI 设计师。请为 CatTV 猫咪吃饭决策机设计一套完整的小屏幕用户体验界面。

项目背景：
CatTV 是一个猫咪头、猫咪耳朵形态的小硬件。它不是手机 App，也不是网页。它可以磁吸在冰箱、背包、手机背后、自行车或桌面支架上。猫头核心可以拆下来独立使用。用户主要通过语音和左右耳/左右滑动操作，因为屏幕很小，不适合打字。

核心功能：
用户不知道今天吃什么，CatTV 通过语音收集想法，结合用户资料、过敏忌口、口味、预算、时间、人数、吃饭场景、距离、历史记忆，让多只猫咪 Agent 开会，最后推荐安全合适的食物。用户可以换一个、确认、扫码到手机继续下单，也可以进入外卖盲盒随机决定。系统永远不自动支付。

技术语境：
这是一个本地 AI 小硬件产品。界面要体现“小屏硬件”和“猫咪议事会”，但不要画成科技感大屏，也不要画成手机 App。

屏幕规格：
- 画布尺寸：448 x 368 px
- 横屏
- 安全边距至少 24 px
- 适合小硬件屏幕远看
- 文字必须少，大部分真实文字留给程序员用代码渲染
- 每页需要输出两版：1. 完整效果预览 preview_full；2. 无文字背景 bg_no_text

整体风格：
- 治愈、温暖、猫咪、轻游戏感
- 像一个有点吊儿郎当但可靠的小猫助手
- 不要赛博朋克，不要冷冰冰科技风，不要手机 App 风
- 可以有猫爪、纸条、便签、小票、圆桌、食物卡、盲盒、磁吸小硬件元素
- 颜色温暖但不要全部是同一种棕色/橙色；需要清晰层级

硬件和交互必须表达：
- 猫咪头和猫耳是硬件本体
- 首页有两个入口：“今天吃什么”和“我饿不饿”
- 语音是主要输入方式
- 左耳/左滑 = 换一个 / 不要
- 右耳/右滑 = 就这个 / 确认
- 扫码只是手机接力，人类最后确认下单，机器不代付

重要安全边界：
- 过敏、忌口、强烈讨厌的食物必须被排除
- 经期、心率、呼吸、微米波状态只能作为用户自填/传感器辅助的温柔提醒，不要表现为医疗诊断
- 幸运食物是类似星座/MBTI 的娱乐玩法，不要表现成严肃算命或健康处方
- 食物知识提醒是本地温柔提醒，不要夸张成医疗建议

请生成以下 20 个页面。每一页都要适合 448x368 小屏，构图清楚，文字少，主视觉明确。

01_idle_start 首页/待机：
画面是猫咪硬件待机，猫咪在屏幕里看着用户。两个大入口按钮：今天吃什么、我饿不饿。要有语音唤醒/猫爪按钮感觉。不要密集菜单。

02_profile_setup 用户资料：
收集怎么称呼用户，比如 Abby。性别/称呼可选：女生、男生、不区分、跳过。不问年龄。可选生日和出生时间，为幸运食物玩法预留。画面要像猫咪拿着小档案卡，不要像表格。

03_care_profile 照护状态：
用户可选健身、节食、正常吃、想放纵、经期照护、规律吃饭。经期只作为用户自填选项，不要医疗化。画面要温柔、隐私感强，像猫咪在认真记小纸条。

04_mode_scene_select 模式和场景：
模式：普通决策、外卖盲盒、今日幸运食物、多人吃饭。在家做饭/叫外卖/出去吃/随便。距离选择：1km、5km、10km、不限。画面是猫咪地图/菜单选择台。

05_preference_filter 基础筛选：
辣度、过敏、不爱吃、非常抵触的菜系/食材、预算、多久要吃到、几个人吃。需要明显体现“过敏和忌口是硬规则”。不要做复杂表单，使用大按钮/chips。

06_voice_input 语音输入：
猫咪引导用户说：“今天想吃什么感觉？” 例如没胃口、想吃辣、想吃清淡、不想吃面。画面以麦克风波纹和猫耳收音为主。

07_clarify_question 补问：
如果缺关键信息，猫咪只问一个问题，比如预算多少、多久要吃到、有没有过敏。画面是一只猫从小纸条后探头，下面 3-4 个快捷选项。

08_cat_council 猫咪 Agent 议事会：
多只猫围圆桌开会。显示 6-8 只猫：会长猫、口味猫、觅食/地图猫、安全/过敏猫、记忆猫、时间猫、预算猫、情绪/幸运猫。每只猫有小气泡，但不要塞满文字。感觉是 5 秒内快速讨论。

09_council_bubbles 议事会气泡特写：
同一议事会的动态中间态。1-2 个猫气泡突出，例如口味猫：“避开重辣”，地图猫：“附近有合适的”，记忆猫：“昨天吃过面了”。留空给代码渲染文本。

10_candidate_list 推荐列表：
会长猫总结：“这些可能符合你的胃口”。展示 3-6 个安全候选食物卡，每张卡有图片、价格/时间/距离的小区域。用户可以点选多个能接受的。

11_choose_yes_no 单个推荐确认：
突出一个推荐菜。左边换一个/不要，右边就这个/确认。必须符合左=换/不要，右=确认/要。适合耳朵按钮或左右滑。

12_blind_box 外卖盲盒：
如果用户选了多个菜还是拿不准，进入 4-6 个盲盒。每个盲盒是猫爪盖住的食物卡。点一个后随机揭晓。感觉刺激但安全，强调“已避开过敏/忌口”。

13_qr_order 扫码下单：
显示二维码区域，用手机扫码继续。猫咪把二维码小票递出来。文案区域留给“手机继续确认”。不要表现成机器自动付款。

14_receipt_done 喵单小票：
小票机吐出喵单，显示菜名、价格、预计时间、推荐理由、已避开的风险。猫咪盖章。留空给代码渲染真实内容。

15_food_journal 食物手账：
像一本小手账/翻书。用户左右滑翻页，看自己哪天上午/中午/晚上吃了什么。每条记录可以是小贴纸、小票、小图标。重点是“记忆猫记住你”。

16_lucky_food 今日幸运食物：
基于生日时间、今日灵感、幸运色/方位/五行感做娱乐推荐。画面可以有幸运色、幸运食物、方向罗盘，但要轻松可爱，不要严肃玄学。必须说明这是娱乐玩法。

17_group_decision 多人吃饭：
2-4 人吃饭时，每个人有自己的想吃/不想吃/忌口/预算。画面用人物小头像或猫爪标签表示每个人，不要做复杂表格。对于大型聚会/全班/全公司，用“群体偏好”大按钮，而不是每个人都填。最后显示一个折中方案区域。

18_craving_check 我饿不饿：
微米波/历史记忆辅助。画面是猫咪扫描状态，但不要医疗化。显示上次吃饭记录、当前目标（健身/节食/正常）、传感器小图标。输出像“可能是真饿 / 可能是嘴馋”的温柔判断。

19_home_cooking 在家做饭：
用户选择在家吃时，猫咪根据历史记忆和用户状态推荐简单家常饭。比如很久没吃蔬菜，就推荐清爽蔬菜/水果方向。画面像小厨房或冰箱便签，不要像复杂菜谱 App。可显示食材/难度/理由区域。

20_food_knowledge_note 食物知识提醒：
安全/照护猫给一张便签，例如“如果正在服药或有特殊情况，请以专业建议为准”。只做温柔提醒，不要吓人，不要说治疗。适合本地知识库弹出。

每页输出要求：
- 生成 preview_full.png：完整效果预览，可含少量示例文字。
- 生成 bg_no_text.png：去掉功能性文字，只保留背景、角色和装饰。
- 如果有角色、按钮、食物、气泡，请建议拆成透明 PNG。
- 每页留出清晰文字区域和按钮区域。
- 不要把真实价格、菜名、理由画死；这些由程序动态渲染。
- 不要画手机 App 状态栏。
- 不要画过多解释文字。
```
